## 0. Конвейер в одну строку

`kmd-generate (нейро-данные .f32)` → `probe_hand_path.gd (числовой гейт хореографии)` →
`compose/mirror при нужде` → `retarget_soma_anims.gd (в shared_animations.res)` →
`test_soma_invariants.gd` → `test_cast_anims.gd` → `смоук арены` → `перезапуск игры`.

**Железное правило: мусорная генерация НЕ ДОЕЗЖАЕТ до игры** — каждый этап отсеивает
своё (нейро-мусор ловит гейт ДО ретаргета, ошибки математики — тесты, регресс — смоук).

## 3. Формат данных и скелет SOMA30

- `root_positions.f32` — frames×3, метры, глобальная позиция таза (Hips). **Высота роста (~0.97 м)
  живёт ЗДЕСЬ**, не в офсетах.
- `local_rotations_xyzw.f32` — frames×30×4, **XYZW** (не WXYZ!), ЛОКАЛЬНЫЕ кватернионы.
- Скелет: 30 суставов, T-поза, Y-up, лицо +Z; rest-повороты = identity (⇒ FK-глобал кости = её
  дельта от T-позы — на этом стоит ретаргет v2). Имена/родители/офсеты — дословно из
  `src/skeleton.hpp`, продублированы константами SOMA_* в конвертере, пробнике и тесте.
- Парность: 8↔9 глаза, 10↔16 плечи, 11↔17 руки, 12↔18 предплечья, 13↔19 кисти, 14↔20/15↔21 пальцы,
  22↔26/23↔27/24↔28/25↔29 ноги. (Константа MIRROR_PAIR в mirror_cast_push.gd.)

## 4. Промпт-инжиниринг (главные грабли датасета)

**Общий урок: слово = СЦЕНАРИЙ.** Нейросеть тянет из датасета типовой сценарий слова целиком,
даже если в промпте описано другое. Проверенные приоры:

| Слово в промпте | Что делает модель | Вывод |
|---|---|---|
| `handgun`, `pistol` | ДВУРУЧНЫЙ хват (данные — стрельба с двух рук) | СЛОВО НЕ ИСПОЛЬЗОВАТЬ |
| `cast a spell` | Двухрукий симметричный пуш (сильный two-arm-приор) | Не годится для однорукого каста |
| `punch`, `punches forward` | **Боксёрская стойка**: рука стартует У ЛИЦА (гард) и в неё же возвращается | Только с явным «starts hanging straight down… never rises to the face first» + гейтом старта |
| «стоит спокойный человек» (ЛЮБОЙ промпт) | **Гард-приор датасета**: кисти в стойке у лица/груди С k0 | Промптом НЕ лечится (6 сидов подряд: панч-от-низу, shove, handshake — все y1.30–1.48 на k0). Лечится РЕМАП-КОМПОЗИТОМ (§7) |
| `handshake` | Правая поднимается и вытягивается, ЛЕВАЯ ОСТАЁТСЯ ВНИЗУ | Лучший якорь «правая активна, левая висит» |
| `points straight ahead with index finger` | То же для ЛЕВОЙ руки | Зеркальный якорь |

**Правила написания промпта:**
1. Явно описать НАЧАЛЬНОЕ положение (иначе модель возьмёт типовое для глагола): «both arms
   hanging relaxed at the sides», «the right arm starts hanging straight down at the hip».
2. Явно запретить лишнее: «never rises to the face first», «never rises above the waist»,
   «stays below shoulder height».
3. Явно описать КОНЕЧНОЕ: «returns down to hang relaxed at the side».
4. Вторая рука прописывается отдельно (иначе уедет в зеркальный жест): «The left arm hangs
   relaxed at the left side the whole time».
5. Даже идеальный промпт = лотерея по сидам → несколько сидов + числовой гейт.

**Композит (когда вторая рука всё равно не опускается):** панч-промпты упорно держат левую в
гарде. Решение — сшивка ДАННЫХ покадрово: `Generators/compose_cast_push.gd` копирует цепь
суставов донора (SOMA-индексы левой руки [10,11,12,13]) из клипа с висящей рукой в целевой
клип (правая рука/корпус/ноги — от панча). Источники — оба 24f, иначе отказ.

## 5. Гейты хореографии — `Generators/probe_hand_path.gd`

FK по всем кадрам RAW SOMA, метрики кистей/бёдер, вердикт PASS/FAIL по типу. **Гонять ДО
ретаргета, парами `-- <type> <dir>`.** Типы (пороги в файле, тут смысл):

| Тип | Проверяет | Пойманный баг |
|---|---|---|
| `cast_push` | Правая: толчок z≥0.40 на высоте груди y∈[1.05,1.45]; замах ≤1.50; **dwell**: кисть у лица (y>1.30) при z<0.45 ≥3 кадров = брак; левая висит (y<1.10, z<0.35) | «волейбол», гард-старт И гард-пауза mid-клипа («сначала ко лбу, потом каст») |
| `cast_push_l` | То же зеркально (левая толкает, правая висит) | Ошибка самого зеркала данных |
| `left_bent_front` | Донор пассивной руки: L_z_min≥−0.05 (не за спиной), L_z_max≥0.12 (впереди), L_y∈[0.60,1.20] | «висящая уходит за спину» (вердикт юзера раунда 7) |
| `pistol_shoot` | Правая вытянута z≥0.45 при y∈[1.10,1.65], левая низко всю клипу | «двумя руками держится в центре» |
| `pistol_shoot_l` | Зеркально | левая не вытягивалась (z0.18) |
| `throw` | Замах: ∃кадр y≥1.55 при z≤0.15; выброс: ∃кадр z≥0.35 при y∈[1.05,1.70] | бросок без замаха/выброса |
| все | Бёдра \|y−0.93\|≤0.20, снос xz<0.35 | уход с места, присед |

**Урок гейта:** гейт проверяет ВСЮ траекторию, а не только «главный момент». Гард-старт
прошёл бы любой гейт «максимумов» — кисть у лица не превышает порог замаха. **Dwell-гейт
семантически сильнее точечных проверок старта/финиша**: ловит и гард-старт, и паузу у
лица mid-клипа, при этом корректные бленды/обрезки проходят (кисть у лица БЕЗ выноса —
вот что бракуется).

**Печать PATH** (каждый 4-й кадр, L/R: x/y/z кисти) — главный инструмент диагноза «почему
выглядит криво»: показывает, ГДЕ именно хореография ломается (старт, пик, шов, возврат).

## 6. Ретаргет v2 — `Generators/retarget_soma_anims.gd`

**Математика (единственно верная):**
```
R_out_global(кость, t) = Δ_src(сустав, t) · R_mix_rest_global(кость)   # источник СЛЕВА
hips(t) = rest_скина + (root_positions(t) − root_positions(0))          # ТОЛЬКО дельты root
origin кости = глобал родителя · rest-локал цели                        # длины = цели
локальный кват цели = (глобал родителя)⁻¹ · глобал кости
```
У SOMA rest=identity ⇒ FK-глобал сустава = его мировая дельта от Т-позы. Дельта применяется
ПОВЕРХ rest-базиса скина слева (мировые плоскости движения сохраняются), roll каждой кости
якорится к rest скина (скин шейден к нему).

- **Нейтраль = ПОЛНЫЙ FK кадра 0 клипа** (root_positions + кваты) — высота бёдер источника НЕ
  переносится (она уже в rest скина). Аналитическая Т-поза из офсетов — ТОЛЬКО для side-чека.
- **side_flip**: разово по знаку X кисти SOMA vs скина (SIDE CHECK в логе; сейчас false).
  При flip свапаются ИМЕНА суставов в карте, не математика.
- **Шов лупа** (Cast_Loop): кроссфейд хвоста на обратную голову — `out[L+i]=slerp(M(L+i),M(N−1−i),w)`,
  w→1 ⇒ последний кадр = кадр 0 ТОЧНО (ловится зондом шва: было 43° на кисти).
- TASKS: имя в библиотеке → каталог neuro_soma. LEGACY-имена вычищаются при сохранении.
- Инвариант-принт HIPS OK/WARN — левитация видна в логе ретаргета ещё до тестов.

**ЗАПРЕЩЁННЫЕ способы (все проверены на практике — §11):** конъюгация дельт (R_mix·Δ),
зеркало конъюгацией на уровне рига, перекрёстное применение мировых дельт (SIDE_SWAP).

## 7. Композиты и зеркала — только на уровне ДАННЫХ

### 7.1 Ремап-композит `compose_cast_push2.gd` (стандарт против гард-приора, раунд 7)

Когда промпт-лотерея не пробивает приор датасета (§4), клип собирается детерминированно:

```
база = донор left_bent_front (спокойный торс, левая согнута СПЕРЕДИ, тип гейта left_bent_front)
правая цепь [16,17,18,19] = прививка из панч-клипа В ГЛОБАЛЬНОМ пространстве:
    q_local(первый сустав)  = (B_донор-родителя⁻¹ · B_панч_сустав).rot
    q_local(остальные)      = (B_панч_родителя⁻¹  · B_панч_сустав).rot   # финал родителя = панч
    + жёсткий питч вниз PITCH_DOWN_DEG (конъюгация по финальному родителю каждого сустава)
таймлайн: k0-4 подъём (idle → панч k9), k5-12 толчок (панч k9..k16), k13-23 возврат
    (w = 1 − smoothstep — вес идёт ОТ панча К idle; инверсия = «застывшая рука»!)
```

**Три жёстких урока, вбитых в этот генератор (все пойманы гейтом/зондом):**
1. **Копия ЛОКАЛЬНЫХ ротаций цепи между клипами с разными торсами = мусор** (рука ушла
   y1.59/z0.29 вместо толчка): локали имеют смысл только в системе родителя. Прививка —
   в глобальном пространстве, первый сустав якорится к цели, остальные — к СВОЕМУ
   источнику (родитель после прививки = глобал источника; иначе ошибки компаундятся).
2. **Разная высота стойки компенсируется питчем руки, не подгоном торса**: донор стоит
   выше панча (плечо 1.42 vs 1.25 — панч в подседе), ноги донора не согнуть (упрутся в
   пол). Жёсткий питч всей цепи вниз на 15° в мире ложит кисть с высоты плеча на грудь.
   Мерить `probe_torso.gd` ДО проектирования компенсаций ( hips y, Chest y, плечо, кисть).
3. **Вес фазы возврата — от источника К idle** (`w = 1 − smoothstep`): инверсия даёт
   «застывшую вытянутую руку» в хвосте (гейт-PATH показывает одинаковые k12–k23).

Момент толчка нового клипа: пик z@k9 ≈ 0.30 с (spawn_delay 0.35 с SkillDB попадает
в окно выноса k5–k13 — ок).

### 7.2 Зеркала — только зеркало ДАННЫХ

`Generators/mirror_cast_push.gd` (образец для любых зеркал): покадрово
- кватернион q=(x,y,z,w) → (x,−y,−z,w)  [отражение через YZ: ось n→(−nx,ny,nz), угол −θ];
- обмен L/R-слотов суставов (MIRROR_PAIR, инволюция);
- корень x → −x.

Пишет зеркальный каталог neuro_soma/<clip>_l. Ретаргет дальше обрабатывает его как обычный
клип (каждая целевая кость якорится СВОИМ rest — rest-асимметрия mixamo гасится как твист
и детей не смещает). Контроль точности: гейт зеркала обязан дать числа, зеркально равные
оригиналу (L_z_max == R_z_max оригинала и т.д.), + инвариант-тест SKIN≈RAW.

## 8. Спавн-тайминг и эффекты (чтобы снаряд вылетал ИЗ жеста)

- **Инста-каст = анимация + отсроченный спавн.** `Effect.gd` (базовый класс всех эффектов)
  содержит statics `hand_pos(caster, side)` / `find_skeleton(node)` — живая позиция кисти
  миксамо-скина (фолбэк тело+1.2 м). `SpellCasterComponent` кладёт `"hand"` в context.
- `SpawnProjectileEffect` / `SpawnHomingProjectileEffect` / `SpawnHomingHealProjectileEffect` /
  `SpawnHitscanEffect` — `@export spawn_delay: float` + `@export spawn_from_hand: bool`:
  apply() ждёт `tree.create_timer(spawn_delay)`, ПОТОМ валидирует caster/target, берёт живую
  кисть и спавнит. **⚠ Хоуминги наследуют Effect НАПРЯМУЮ (не SpawnProjectileEffect!)** —
  spawn_delay добавляется в каждый файл отдельно (однажды смоук поймал «Invalid assignment
  'spawn_delay'» именно из-за этого).
- **spawn_delay берётся из гейта клипа** (момент выброса в кадрах ÷ 30): cast_push толчок
  k12 → 0.35 с; Cast_Shoot выброс k8 → 0.3 с. НЕ t=0 (снаряд улетал раньше жеста — вердикт
  юзера), НЕ «на глаз».
- У снаряда с метой звука удара (`impact_sound` → meta «impact_sfx») мета ставится/стирается
  КАЖДЫЙ каст: сцена снаряда шарится пулом между скиллами (иначе звук «прилипает»).
- Канальные скиллы (cast_time): Enter → Loop → по таймеруShoot + execute; прицел берётся
  ЗАНОВО после канала (`_aim_context` — метеор/гром летят по прицелу ВЫБРОСА). Смена сцены
  в канале безопасна (is_instance_valid).

## 9. Защита каст-клипов в игре

`PlayerAnimationComponent.gd`: CAST_ANIMS-список — пока каст-клип играется, локомоция
(Idle/Run/Falling) НЕ съедает его за кадр (hold до конца клипа + бленд 0.15). Новый каст-клип
→ добавить имя в CAST_ANIMS, иначе Falling/Idle перебивает его мгновенно (было поймано
test_cast_anims). Тест CAST-TEST проверяет: клипы на месте, Throw играется, канал
Enter→Loop→Shoot проходит.

30. **Ретаргет из Z-up источника (UAL FBX) — конъюгация мировых дельт осевой
    матрицей S**: источник живёт в chain-осях (up=+Z, fwd=−Y, right=−X), скин —
    в Y-up (up=+Y, fwd=+Z, right=−X); T-позы ригов совпадают под
    S = rotX(−90°). Мировые дельты от нейтрали ОБЯЗАНЫ конъюгироваться:
    `R_out(b,t) = S·(A_b·gT_b⁻¹)·S⁻¹·mix_rest_b` (глобаль скина),
    локаль = `parent_W⁻¹·W_b`, pelvis = `mix_rest.origin + S·(A_pos−gT_pos)`.
    Без S дельты читаются в чужих осях: up источника (+Z) ложится в fwd скина
    (+Z) → бок/фронт меняются местами («зеркало»: леворукий каст приходит
    праворуким, pelvis уносит вбок). v3 с per-bone константами C_b спину
    спасала случайно (её C_spine ≈ S), руки — ломала (5–16° ≠ 90°).
    Диагностическая цепочка перед правкой формулы: оси источника по носкам и
    кресту ключиц (probe_ual_axes), оверлей T-поз под S, равенство
    runtime == предсказанию на живом скелете через set_bone_pose_rotation +
    get_bone_global_pose (probe_apply_pred). Визуальный вердикт — сравнение
    ЛИЦОМ к камере: манекен UAL смотрит −Z, без `rotation.y = PI` его рук не
    видно и сторона каста не сравнима.

### §13.1 Зеркало клипа под другую руку (референс: Generators/build_heart_cast.gd)

Наивная конъюгация локалов на mixamo-риге ЛОМАЕТ позу (коммит 49d1088: 176.71°
на RightShoulder). Правильный рецепт — иерархическое зеркало по глобальным позам:

1. Глобалы кадра: `loc[i] = rest[i]`, затем треки **сливать** (кость с ротацией
   И позицией — например Hips — берёт basis от rot-трека и origin от pos-трека;
   «последний трек wins» стирает ротацию — баг, пойманный на сердечках).
   `g[i] = g[parent] * loc[i]` (родители раньше детей в индексах Godot).
2. Зеркало: `gm[partner(i)] = M·g[i]·M`, M = diag(-1,1,1); партнёр = Left↔Right
   replace в имени, центральные кости — сами себе.
3. Локалы зеркала: `L' = gm[parent(p)]⁻¹ · gm[p]`; в клип пишем ТОЛЬКО ротации
   (+ позиционный трек Hips). Транслеции остальных костей берутся из rest:
   писать позиционные треки рукам НЕЛЬЗЯ — игра обнуляет x/z всем позиционным
   трекам (PlayerAnimationComponent).
4. Сквозная самопроверка в генераторе: готовый клип пересчитать так же, как его
   считает Godot, и сравнить с M·G·M — допуск ~1 см (асимметрия rest mixamo).
5. Кадровая проверка обеих версий до игры (§11.27), клипы склейки: шов стыка
   считать дифом последних/первых ключей (Enter→Exit = 0° — hold-поза общая).

Склейка фаз в один insta-каст: треки A как есть, треки B теми же путями со
сдвигом на A.length (build_heart_cast.gd::_concat).

### §13.2 Поле Skill.cast_hand — снаряд из анимированной руки

cast_anim играет ОДНУ руку (Cast_Shoot — левую, Throw — правую). Чтобы снаряд/
луч вылетал из ЭТОЙ кисти, у Skill есть `cast_hand` ("Right"/"Left", по умолч.
Right): SpellCasterComponent кладёт его в context["hand"], эффекты спавнят из
живой кости `mixamorig_<hand>Hand`. `alternate_hands=true` перекрывает cast_hand
(попеременно Л/П, левая версия анимации = `<cast_anim>_L`).
