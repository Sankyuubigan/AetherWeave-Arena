# МЫШЬ И UI — ССОТ (v2, 19.11.26, после двух раундов регрессий)

Одно правило на всю игру. Любой новый UI обязан ему следовать — тогда мышь не
сможет «пропасть», «залипнуть» или конфликтовать, сколько бы меню ни появилось.

## Правило: у мыши ровно два легальных владельца захвата

1. **Захват (CAPTURED) ставится только в двух местах:**
   - `Logic/PlayerController.gd → _unhandled_input` — ЛКМ по пустому месту
     мира. Клик по живому GUI-контролу до `_unhandled_input` НЕ доходит
     (его съедает GUI) — эвристик «под курсором контрол?» не нужно.
   - **Закрытие любого окна UI** — `Input.set_mouse_mode(CAPTURED)` прямо в
     обработчике закрытия (вердикт юзера 19.11.26: «когда закрывается окно
     (книга навыков), мышь автоматом не фокусится на игру. исправь»).
     Пользователь выходит из меню → курсор сразу в игре, без лишнего клика.

2. **Открытие любого UI → `MOUSE_MODE_VISIBLE`** (UI нужен курсор).

3. **Пока UI открыт, захват заблокирован гейтом**
   `PlayerController._gui_blocks_capture()`: проверяет ТОЛЬКО надёжные
   флаги открытости — `SkillMenu.is_open`, `/root/SettingsMenu.is_open`,
   группу `npc_dialog_open` (NPCTeleporter). Новый UI = добавить свой
   `is_open`-флаг в этот гейт (одна строка).

4. **Страховка-гард в `_process` каждого окна:** пока МОЁ окно открыто —
   мышь VISIBLE. Разруливает пересечение двух окон (закрыл F2 при открытой
   книге: F2 капчурит, гард книги возвращает VISIBLE). Гард — 3 строки,
   копируется из SettingsMenu/SkillMenu.

5. **ESC в игре отпускает мышь** (`PlayerController._input`, только при
   захваченной мыши). Обратно — клик по миру ИЛИ открыть/закрыть любое окно.

## Вращение камеры — отдельно от захвата

Mouse-motion обрабатывается в `_input` (сырой ввод), НЕ в
`_unhandled_input`: при захваченной мыши STOP-контрол под «виртуальным
курсором» глотает события до `_unhandled_input` — камера «умирала».

## Чек-лист нового меню (30 секунд)

- [ ] Панель скрыта при старте (`panel.hide()` / `layer.visible = false`),
      root-контролы без `PRESET_FULL_RECT + MOUSE_FILTER_STOP` в видимом
      состоянии (full-rect STOP, оставшись видимым, съедает ВСЕ клики мира).
- [ ] Открытие: `is_open = true`, показать панель, мышь → VISIBLE.
- [ ] Закрытие: `is_open = false`, скрыть панель, мышь → CAPTURED.
- [ ] `_process`-гард «моё окно открыто → VISIBLE» (скопировать из SettingsMenu).
- [ ] Флаг открытости добавлен в `_gui_blocks_capture()` (PlayerController).
- [ ] Клавиша toggle — через `_unhandled_input` (не перехватывает печатаемый
      текст, LineEdit-фокус не ломается).

## Почему так (история регрессий, не повторять)

- **v0:** захват по ЛКМ в `_input` без гейта → первый клик по ползунку F2 /
  карточке телепорта уходил в капчур, GUI его не видел.
- **v1:** гейт в `_input` по `viewport.gui_get_hovered_control()` → эвристика
  блокировала захват ВСЕГДА → «мышь не фокусится в игру больше никак».
- **v2 (итог, вердикт юзера):** захват в `_unhandled_input` + флаги
  открытости; на закрытии UI — автозахват. Первый вариант v2 «закрытие UI
  мышь не трогает» юзер забраковал: без клика после закрытия мышь не
  возвращалась — «это баг». Автозахват на закрытии безопасен: гонки v0
  были в захвате по КЛИКУ, а не по факту закрытия окна.

## Гейт регрессии

```bash
# CAPTURED в коде — только PlayerController (клик по миру) + закрытия UI
# (SkillMenu/SettingsMenu/NPCTeleporter в ветках is_open=false):
grep -rn "MOUSE_MODE_CAPTURED" --include="*.gd" Logic/ Graphics/
```

Новый `set_mouse_mode(CAPTURED)` вне этих путей = нарушение ССОТ.
Проверка логики: `Generators/probe_mouse_gate.gd` (MOUSE-GATE ALL PASS).
