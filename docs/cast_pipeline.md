# Конвейер каст-анимаций: UB-запечка, слои, IK и хендпоузы

ССОТ по анимациям кастов. Отвечает на вопросы: откуда берутся каст-клипы, почему
их два вида (full-body / UB), кто и когда их играет, что нельзя ломать.
Нейро-генерация отдельных клипов — `docs/animation_generation.md` (§11 — реестр ошибок).
Игровые скиллы/каналы/прицел — `docs/skill_system.md`.

## 0. Одной строкой

`FBX источников → retarget → композиты/зеркала (данные) → build_cast_fb (yaw таза = 0) →
build_cast_ub (срез верх/низ) → ual_casts_test.res → CastAnimationLayer → CastPlayer`
в игре поверх локомоции; каст выбирает FB (стоит) или UB (бежит) по скорости и полу.

## 1. Два плеера, один скелет

| Что | Где | Пишет |
|---|---|---|
| Локомоция (Idle/Run/Falling/Jump) | `AnimationTree` на `GraphicsWrapper/AnimationPlayer` | всё тело, каждый кадр |
| Касты | **CastPlayer** (`Graphics/CastAnimationLayer.gd`) | поверх: добавлен в дерево ПОЗЖЕ, `root_node` тот же |

`CastAnimationLayer` — фасад (Ф2.1/2.2, вердикт спеца 23.11.26): скиллы и
`SpellCasterComponent` знают только API `has_cast_anim / play_cast_anim /
cast_clip_length / play_channel / end_channel`. Внутренность (CastPlayer) заменяема
в одном файле: объединённое дерево OneShot/Blend2 отложено — визуально не
верифицируется в headless, а своп рискует регрессом одобренных кастов.
`PlayerAnimationComponent.cast_player` оставлен как getter-совместимость для гейтов.

Блендинга между плеерами НЕТ (это не AnimationMixer-кроссфейд). Поэтому:
- вход в каст — `stop()` → `play(clip, 0.1)` → `capture(clip, 0.1)`: `capture()`
  доводит из ТЕКУЩЕЙ позы, иначе рывок через rest-позу;
- `stop()` перед рестартом — спам одного скилла не копит смещения (фикс раунда 14);
- выход из UB-каста — хвост 0.2 с в клипе, возвращающий верх в позу Idle
  (`TAIL_CLIPS` в `build_cast_ub.gd`): при остановке CastPlayer верх мгновенно
  становится позой локомоции, хвост сводит скачок к разнице Idle↔Run.

## 2. Цепочка сборки библиотеки (порядок обязателен, все шаги идемпотентны)

```
Generators/retarget_ual_anims.gd   # UAL (Unity/UE Mannequin) → mixamorig_ скина Ch24
Generators/build_heart_cast.gd     # Heart_Cast = Cast_Enter+Cast_Exit, Heart_Cast_L — зеркало
Generators/build_cast_fb.gd        # во ВСЕХ не-UB клипах yaw таза = 0   ← должен быть до UB
Generators/build_cast_ub.gd        # из каждого клипа строит <Имя>_UB (верх тела)
```

Запуск: `Godot_v4.8-beta3_win64_console.exe --headless -s res://Generators/<script>.gd`.
Выход всей цепочки — `Graphics/Animations/ual_casts_test.res` (тестовая библиотека;
`shared_animations.res` занят нейро-клипами).

- **Ретаргет** (`retarget_ual_anims.gd`, v4): `R_out = S·(A_b·gT_b⁻¹)·S⁻¹·mix_rest_b`,
  `S = rotX(−90°)` (конвертация up=+Z → up=+Y). Нейтраль — T-поза пака (`A_TPose`),
  rest-поза цели — **скин игрока**, не Idle.fbx (rest Idle расходится до 90° на кистях —
  «кукла»). Горизонтальный root motion обнулён (in-place).
- **Композиты и зеркала — только на уровне ДАННЫХ** (урок §7.2 `animation_generation.md`):
  зеркало иерархическое по глобальным позам `G'[partner(b)] = M·G[b]·M`, `M = diag(−1,1,1)`.
  Наивная конъюгация локалов ломает риг (коммит 49d1088: 176.71° на RightShoulder).

## 3. Два вида клипа: full-body и UB

| | full-body (`<Имя>`, без суффикса) | UB (`<Имя>_UB`) |
|---|---|---|
| Что внутри | Hips (позиция+ротация) + ноги + верх, 21 трек | только верх, 12 ротационных треков |
| Когда играет | **СТОЯ**: `speed < 0.2` И `is_on_floor()` | **В ДВИЖЕНИИ** (бег/падение) |
| Кто выбирает | `PlayerAnimationComponent.play_cast_anim()` → `play_full_body()` | `else` → `play_cast_anim()` (UB) |
| Зачем | шаг/присед/ступни на полу — ноги не «забетонированы» | локомоция ведёт низ, каст — верх |

Инварианты (проверяются гейтами, ломать нельзя):
1. **В UB НЕТ ни одного трека Hips и ни одной ротации 8 костей ног.** Железное
   правило спеца «Hips НИКОГДА в upper-body». Нарушение = таз крутится до 56° и
   уносит ноги (отчёт спецу §7).
2. **В full-body клипах yaw таза = 0.** Направление тела — дело кода
   (`face_aim_target` / ввод), не клипа. У UAL-исходников yaw был −41°…+117° и
   разный по клипам: стоя игрок разворачивался лицом в камеру (баг 26.11.26,
   видео юзера). Пити/ролл и позиция сохраняются (наклон, присед).
   Соглашение осей (модель смотрит в +Z при yaw 0) — §7.1.
3. **Hip-to-Spine Transfer УДАЛЁН** (23.11.26): перенос тазовой дельты в Spine1
   загибал спину под 90° (Spine1 yaw 100° pitch 65° вместо 12/12). Не возвращать.
4. Non-rotation трек в full-body допустим ровно один — **позиция Hips**;
   любой другой не-ротационный трек = баг.

## 4. Каналы (cast_time > 0)

Длительный каст — `SpellCasterComponent.cast_skill()`.

### 4.1 Классический канал (cast_anim пуст)
`play_channel()` → `Cast_Enter_UB` → (сигнал `animation_finished`) → `Cast_Loop_UB`
(цепочка живёт в `CastAnimationLayer._on_finished`) → по таймеру `cast_time`
`end_channel()` → `Cast_Shoot_UB` + `execute()`.

### 4.2 Канал СО СВОИМ КЛИПОМ (26.11.26 — метеор, гром)
`Skill.cast_anim` у канала РАНЬШЕ ИГНОРИРОВАЛСЯ (всегда Enter→Loop→Shoot) — юзер
выбирал двуручные клипы, а играл старый UAL-канал. Теперь:

| шаг | что происходит |
|---|---|
| старт | `play_channel(clip, fit_speed)` — клип `clip_UB` играет **один раз** |
| темп | `cast_fit_speed(clip, cast_time)` = `raw_len / cast_time`, кламп 0.25–4.0 |
| конец | `end_channel()` НЕ подмешивает `Cast_Shoot` (`_channel_custom`) |
| выброс | приходится ровно на `execute()` — клип растянут в окно канала |

Замеры: `Cast_2H_Area_01` 2.97 с → окно 2.0 с = темп 1.49;
`Cast_2H_Magic_01` 2.70 с → окно 1.0 с = темп 2.7.
`cast_raw_length()` отдаёт длину БЕЗ деления на текущий темп (иначе повторный
каст считал бы темп от уже ускоренного клипа).

### 4.3 Общее для каналов
- `is_channeling()` гасит движение/прыжок в `PlayerController`; ноги при этом живут
  (Idle/Falling под UB-верхом — тот же приём, что и для инсты).
- Повторные касты во время канала заблокированы («Идёт другой каст»).
- **Прицел берётся ЗАНОВО в конце канала**: метеор/гром ложатся туда, куда смотришь
  при выбросе (запрос юзера 17.11.26), а не при старте.
- Полоска каста — свой `CanvasLayer` (у FFA-ботов глушится `show_cast_bar = false`).
- Клипы long-cast: `Cast_Enter` 0.53 с, `Cast_Loop` (луп), `Cast_Shoot`, `Cast_Exit`.
- **Алиасы имён**: части UAL-клипов в игре нет — `CastAnimationLayer.UAL_CAST_ALIASES`
  (`Cast_Shoot_L` → `Pistol_Shoot`) подставляет реальное имя и добавляет `<alias>_UB`
  в библиотеку CastPlayer. Новый алиас — только сюда, не в `SkillDB`.

## 5. Инста-касты, отмена, ОЧЕРЕДЬ и КЛИП-СОСТОЯНИЕ

### 5.1 Инста и окно отмены
`cast_time == 0` → `play_cast_anim(skill.cast_anim)` + `execute()` сразу.
Правила отмены/приоритетов — `docs/animation_generation.md` §14 (стандарт проекта):
инста-касты отменяемы после порога проигрыша (`cancel_at`), каналы коммитятся.

**ИНВАРИАНТ 26.11.26 (заряд): окно отмены ≥ `spawn_delay` + 0.05 с.**
Каст нельзя прервать раньше, чем сработал его отложенный эффект. Иначе спам
перезапускает клип ДО спавна и снаряд рождается из позы СЛЕДУЮЩЕГО клипа
(сердечко: окно 0.68 с, спавн 0.85 с → сердце из боковой позы, жалоба юзера
«руки влево/вправо вместо вперёд»).

Формула живёт ТОЛЬКО в `SpellCasterComponent.cancel_fraction(sk, insta_len)`
(static). Гейт `probe_spawn_sync.gd` вызывает её же — дублировать формулу в
тесте запрещено (два места = расхождение; уже ловили на `_zero_hips_yaw`).

**`spawn_delay` — РЕАЛЬНОЕ время, а не время клипа.** При `cast_speed = 2.0`
клип уходит вдвое дальше: спавн 0.67 с реальных = 1.34 с клипа (фаербол).
Обратное тоже верно: при замере позы для спавна искать надо
`delay * cast_speed` в треках.

### 5.2 Очередь клипов `next_cast_anim` (26.11.26 — энергоклинок)
Вердикт юзера: «не отменять удары, а ставить их в очередь». `Blade_Swing_A`
игрался ОДИН раз и обрывался спамом (эффект сам звал `play_cast_anim`).

| поле | смысл |
|---|---|
| `Skill.cast_anim` | клип первого удара круга (A) |
| `Skill.next_cast_anim` | клип второго удара (B); дальше круг A→B→A… |

Железные правила (гейт `test_blade_queue.gd`, 7/7):
1. Очередь живёт в `SpellCasterComponent` (`_queue_next`), НЕ в эффекте.
2. Продвижение — ТОЛЬКО при фактическом `play_cast_anim` (в окне отмены или из
   буфера ввода). Спам не проскакивает клипы авансом.
3. Условие продвижения — «играли ли клип ОЧЕРЕДИ» (`cast_anim_name != ""`), а не
   `== skill.cast_anim`: у энергоклинка первый каст идёт в режиме материализации
   (`Throw`), и очередь обязана начаться с A, а не с B.
4. Смена скилла сбрасывает очередь.
5. Режим выбирает ЭФФЕКТ хуком `Effect.pick_cast_anim(caster, skill)` (база — "");
   хук ЧИСТЫЙ (только чтение), иначе буфер ввода съедал бы режим.

### 5.3 Клип-СОСТОЯНИЕ `cast_anim_loop` (26.11.26 — крылья)
Поза, которая играет по кругу, пока активен эффект. Это не удар — окна отмены НЕТ.

| API | смысл |
|---|---|
| `Skill.cast_anim_loop = true` | скилл играет `cast_anim` как состояние |
| `play_cast_loop(clip)` | `clip_UB` по кругу, спам НЕ перезапускает |
| `stop_cast_loop(clip)` | гасит; чужое состояние не трогает (сверяет имя) |
| `has_loop_state()` | есть ли активное состояние |

**Владелец гасит сам** (иначе клип «прилипнет» навсегда):
`WingsComponent.deactivate()` → `stop_cast_loop("Wings_Fly")`,
`TetherSwingComponent.release()` → `stop_cast_loop("Tether_Hang")`.
Разовый каст поверх состояния возвращает состояние в `_on_finished` (`_loop_clip`).

### 5.4 Поза стойки `stance_loop_anim` (26.11.26 — бард)
Отдельное поле, а НЕ `cast_anim`: у стойки нет каст-удара, `SpellCasterComponent`
не должен играть её клип одноразово. Владелец — `StanceComponent`
(`enter_stance()` → `play_cast_loop`, `exit_stance()` → `stop_cast_loop`).

### 5.5 Контракт ОДНОГО ВЛАДЕЛЬЦА анимации (обязателен)
`SpellCasterComponent` кладёт в `context["cast_anim"]` имя клипа, который играет
каст-слой. Эффект, увидев непустое поле, **свой жест НЕ играет** — иначе два
клипа рвут друг друга (крылья дёргались `Cast_Enter` поверх `Wings_Fly`).
Проверено в: `SpawnWingsEffect`, `SpawnPortalsEffect`, `SpawnPortals2Effect`,
`TetherSwingEffect`, `SpawnBladeEffect`.

## 6. IK-доводка руки (`Graphics/CastIKComponent.gd`)

2-bone IK поверх UB-клипа: `Arm → ForeArm → Hand` тянется к точке прицела каждый
кадр окна, закон косинусов + доворот от текущего направления, влияние `w` с фейдом.
`SkeletonIK3D` в 4.8-beta не применяется (зонд) — считается вручную в `_process`
компонента (порядок в дереве гарантирует «поверх» анимации).

- `ik_mode` (задаёт `SpellCasterComponent._ik_begin`): `aim_hand` — довод кисти;
  `none` — IK выкл; `look_only` — руки у груди (ведёт LookAtModifier3D).
- `aim_hand` только для физического контакта в пределах руки (`ether_tether`, захват
  троса): на дальних кастах/лучах 2-bone выпрямляет локоть в палку и выворачивает
  плечо — «кукольные руки» (баг спеца). Для остальных — `none`.
- Окно: инста — длина UB-клипа; канал — `cast_time + длина Cast_Shoot_UB + 0.15`.
  После окна влияние плавно → 0 (`FADE_OUT = 0.15`), рука без рывка уходит под клип.

## 7. ОСИ, разворот и прицел (баг 26.11.26 — «перс в камеру»)

### 7.1 Соглашение осей — ЧИТАТЬ ДО любой работы с yaw/прицелом

**Модель Mixamo при `GraphicsWrapper.rotation.y = 0` смотрит в +Z.**
Камера (`SpringArm3D`) стоит СЗАДИ, на +Z, и смотрит в −Z. Значит yaw 0 =
персонаж ЛИЦОМ В КАМЕРУ. «Спиной к камере» = **π**.

```
yaw = atan2(dir.x, dir.z)   → ставит НОСКИ в направление dir
                             (W = локальный −Z = yaw 180°)
```

Проверено замерами, не на глаз: `Generators/probe_model_forward.gd`,
`probe_facing_facts.gd` (носки = Toe − Foot в мировых осях), визуально —
`Generators/render_facing_shots.gd` / `render_facing_fixed.gd` (оконный запуск, PNG).

**`GraphicsWrapper.rotation.y` — ЛОКАЛЬНЫЙ** (обёртка — ребёнок тела, а мышь крутит
само тело через `rotate_y`). Писать в него МИРОВОЙ yaw нельзя: ошибка ровно на
yaw тела. Правильно:

```gdscript
graphics_wrapper.rotation.y = wrapf(yaw_world - rotation.y, -PI, PI)
```

Это ошибка класса «мировое в локальное» — ловилась в трёх местах сразу
(`face_aim_target`, полётный yaw в `_process`, `AimSpineModifier`).

### 7.2 Четыре уровня защиты, все нужны

1. **Данные** — yaw таза в full-body клипах = 0 (§3, инвариант 2). Направление тела задаёт код.
2. **Стартовая поза** — `PlayerController._ready()` ставит `graphics_wrapper.rotation.y = PI`
   (спиной к камере). Без этого игра начиналась с персом ЛИЦОМ В КАМЕРУ — именно это
   юзер и видел как «разворот при касте».
3. **`PlayerController.face_aim_target(aim_point, duration)`** — доворот корпуса к прицелу,
   кламп `CAST_FACING_MAX_DEG = 150°` от ТЕКУЩЕГО мирового yaw (не 180° за кадр).
   Кламп 100° (первая версия) был костылём: он срезал честные довороты и юзер видел
   «поворот стал меньше, будто на 90°». Не опускать без причины.
4. **`SpellCasterComponent._aim_dir_point(player, max_range)`** — направление прицела =
   ТОЛЬКО горизонтальный forward камеры, **без рейкаста**. Рейкаст при камере, наклонённой
   вниз, даёт точку в 0.9–2.6 м от игрока (`probe_aim_repro.gd`); если персонаж стоит
   спиной к камере, направление на такую точку читается как «назад» → разворот в камеру.
   Направление важнее дистанции.

Плюс мягкий прицел позвоночником: `PlayerAnimationComponent.set_aim(point, duration)`
(`AimSpine`-модификатор, вес вход 0.08/выход 0.20, отдача Spine2 — пружина 0.15 с).
`aim_point` там МИРОВОЙ, а позы скелета локальные — `AimSpineModifier` переводит его
в пространство скелета (`skel.global_transform.affine_inverse() * aim`).

### 7.3 ГРАБЛИ (не повторять)

- **Не мерить yaw таза локальным `euler.y`.** У этого скина rest Hips = identity, поэтому
  локальный `euler.y` ≈ 0 у ВСЕХ клипов — «фикс» через обнуление локала был тавтологией
  (мерил тем же, что писал). Правильная метрика — swing-twist дельты rest→поза ВОКРУГ
  МИРОВОЙ вертикали: `2·atan2(q.y, q.w)` от `rest⁻¹·cur` глобальных кватернионов
  (`probe_cast_facing.gd:_hips_twist_deg`, `Generators/probe_hips_rest.gd`).
- **Не проверять гейтом только ДАННЫЕ клипов.** Прежний `probe_cast_facing.gd` был зелёным,
  пока баг жил в коде. Гейт обязан мерить РЕЗУЛЬТАТ: куда смотрят носки после
  `face_aim_target` при разном yaw тела, стартовую позу и наклон камеры.
- **Не «лечить» симптом клампом.** Уменьшение клампа скрывает причину: юзер видит
  «поворот стал меньше», а не «поворот правильный».

## 8. Хендпоузы (пальцы)

UAL/нейро-клипы **без пальцевых треков** — кисть выглядит расслабленной «лопатой».
Решение (вердикт спеца 23.11.26): аддитивный пресет сгиба поверх позы.

- `Graphics/HandPoseLibrary.gd` — 5 пресетов: `RELAXED / FIST / OPEN_CAST / GRIP / POINT`
  (`POINT` = все FIST, кроме указательного). Сгиб фаланги `[прокс, сред, дист]` в градусах,
  кости `mixamorig_<Side>Hand<Finger><1..3>`.
- `Graphics/HandPoseModifier3D.gd` (`SkeletonModifier3D`, применяется ПОСЛЕ анимации):
  вес и пресет ведёт `PlayerAnimationComponent.set_hand_pose(preset, w)` из
  `SkillDB.hand_pose`.
- **Вес 1.0 только для клипов БЕЗ родных пальцев** (нейро/UAL). У Mixamo-клипов пальцы
  свои — модификатор с весом 0 их не трогает.

## 9. Кватернионная гемиспера (`Generators/anim_quat_hemisphere.gd`)

`AnimQuatHemisphere.apply(anim, rest)`: если `q.dot(rest) < 0` для ключа 0 или
`q.dot(prev) < 0` для последующих — кватернион инвертируется. Без этого интерполяция
идёт по ДЛИННОЙ дуге: вывих кисти на 310°. Вызывается в конце `build_cast_ub._make_ub`.

## 12. Чек-лист «новый каст-клип от FBX до игры»

1. FBX в `Graphics/Animations/raw/`, запись в `Generators/build_animations.gd` (если клип
   едет в `shared_animations.res`) или сразу в цепочку UAL (п.2).
2. Прогнать цепочку §2 целиком (порядок!) — FB-фикс и UB-запечка пересоберутся сами.
3. `test_cast_anims.gd` → EXIT=0 и `probe_cast_facing.gd` → `FACING: ALL PASS`.
4. Имя клипа — только в `SkillDB` скилла (`Skill.cast_anim`). Список допустимых имён
   `SkillSerializer.cast_anims()` выводится ИЗ библиотеки (`ual_casts_test.res`, все имена
   без `_UB`) — руками не правится. Проверка: `test_cast_anim_whitelist.gd` → EXIT=0.
5. Зеркало под другую руку — только данными (`build_heart_cast.gd` как референс),
   имя `<Клип>_L`; скилл с `alternate_hands = true` сам чередует (`SpellCasterComponent`).
6. `visual_cast_check.gd` (оконно) — посмотреть кадры глазами.
7. Хендпоуза: клип без пальцев → прописать `hand_pose` в скилле (иначе «лопата»).
8. **Сквозной смоук `smoke_skill_casts.gd`** → `SMOKE: ALL PASS`. Он проверяет
   не только данные, но и РЕАЛЬНЫЙ каст на живом игроке с ловлей `cast_rejected`.
9. Долгий каст (`cast_time > 0`) — `cast_anim` играется ОДИН раз с темпом
   `raw_len / cast_time`; `Cast_Shoot` НЕ подмешивается (§4.2).
10. Непрерывная поза (крылья/трос/стойка): `cast_anim_loop = true` либо
    `stance_loop_anim` + владелец гасит `stop_cast_loop` (§5.3–5.4).
11. Повторяющийся удар A/B: `next_cast_anim` (очередь живёт в кастере, §5.2).
